# 9월 2일 수업내용

## 1. 웹의 기본 개념
### 1.1 웹(Web)이란?

웹의 기본 목적은 인터넷에 연결된 여러 컴퓨터에서 문서를 공유하고 열람하는 것이다.

- 정식 명칭: **World Wide Web**
- 인터넷을 이용해 웹 문서를 주고받는 정보 시스템
- 여러 정보가 하이퍼링크를 통해 거미줄처럼 연결됨
- 웹에서 다루는 문서를 **웹 문서(Web Document)**라고 함

### 1.2 웹의 구성

웹은 크게 **웹 서버**와 **웹 클라이언트**로 구성된다.

| 구분 | 역할 |
|---|---|
| 웹 서버(Web Server) | 웹 문서, 이미지, 동영상 등의 자원을 저장하고 클라이언트의 요청에 따라 전송 |
| 웹 클라이언트(Web Client) | 서버에 웹 자원을 요청하고, 받은 내용을 사용자에게 출력 |
| 웹 브라우저(Web Browser) | 웹 클라이언트 역할을 수행하는 대표적인 소프트웨어 |

대표적인 웹 브라우저에는 Chrome, Edge, Firefox, Opera 등이 있다.

### 1.3 웹 서버와 클라이언트의 동작

```text
1. 사용자가 웹 브라우저에 주소를 입력한다.
2. 웹 브라우저가 해당 웹 서버에 연결을 요청한다.
3. 웹 서버가 연결을 수락한다.
4. 웹 브라우저가 HTML 문서 등의 자원을 요청한다.
5. 웹 서버가 요청받은 자원을 전송한다.
6. 웹 브라우저가 문서를 해석하여 화면에 출력한다.
```

핵심 구조는 다음과 같다.

```text
웹 클라이언트 ── 웹 문서 요청 ──> 웹 서버
웹 클라이언트 <── 웹 문서 전송 ── 웹 서버
```

## 2. 웹 사이트의 구성

웹 사이트를 구축하려면 일반적으로 다음 요소가 필요하다.

1. 웹 서버로 사용할 컴퓨터
2. Apache, IIS, Nginx 등의 웹 서버 소프트웨어
3. HTML 문서, 이미지, 동영상 등의 웹 자원
4. 회원 관리나 주문 처리 등에 사용할 데이터베이스
5. 검색, 로그인, 번역 등을 처리하는 웹 서버 응용프로그램

### 2.1 웹 서버 소프트웨어

웹 서버 소프트웨어의 역할은 다음과 같다.

- 브라우저가 보낸 요청 해석
- 요청에 필요한 서버 응용프로그램 실행
- HTML 문서 또는 응용프로그램의 실행 결과 전송

| 웹 서버 소프트웨어 | 특징 |
|---|---|
| Apache | Apache Software Foundation에서 개발 |
| IIS | Microsoft에서 개발한 웹 서버 |
| Nginx | 높은 성능과 동시 접속 처리로 널리 사용 |
| GWS | Google에서 사용하는 웹 서버 |

### 2.2 웹 서버 응용프로그램

웹 사이트의 구체적인 기능을 서버에서 수행하는 프로그램이다.

예시는 다음과 같다.

- 검색 사이트: 검색 처리
- 번역 사이트: 번역 처리
- 쇼핑몰: 주문 및 결제 처리
- 회원 사이트: 로그인 및 회원 관리

서버 응용프로그램을 개발할 때 사용할 수 있는 기술에는 서버용 JavaScript, JSP, Java Servlet, C/C++, PHP, Perl, Python 등이 있다.

## 3. 웹 문서와 전자 문서

### 3.1 일반 전자 문서

- 워드, 한글, 메모장 등의 프로그램으로 작성
- 하나의 문서를 보통 하나의 파일로 저장
- 텍스트와 이미지 등의 자료가 문서 파일 안에 포함됨
- 문서를 읽는 순서를 작성자가 결정함

### 3.2 웹 문서

- HTML 언어로 작성하고 웹 브라우저로 열람
- 페이지마다 별도의 HTML 파일로 저장
- 이미지, 동영상 등의 자원은 별도 파일로 저장하고 HTML에서 연결
- 여러 페이지가 하이퍼링크를 통해 연결됨
- 사용자가 링크를 선택하면서 읽는 순서를 결정함

| 비교 항목 | 전자 문서 | 웹 문서 |
|---|---|---|
| 작성 도구 | 워드, 한글 등 | HTML 편집기 |
| 열람 도구 | 문서 작성 프로그램 | 웹 브라우저 |
| 저장 방식 | 주로 하나의 파일 | 페이지별 HTML 파일 |
| 이미지·동영상 | 문서 내부에 포함 가능 | 별도 파일을 연결 |
| 읽는 순서 | 작성자가 주로 결정 | 사용자가 링크를 통해 결정 |

### 3.3 하이퍼링크와 내비게이션

- **하이퍼링크(Hyperlink)**: 다른 웹 페이지의 주소를 가진 텍스트 또는 요소
- **내비게이션(Navigation)**: 사용자가 하이퍼링크를 따라 웹 페이지 사이를 이동하는 과정

## 4. URL

**URL(Uniform Resource Locator)**은 인터넷에 있는 웹 자원의 위치를 나타내는 주소이다.

```text
http://www.oracle.com:80/technetwork/java/index.html
```

| 구성 요소 | 예시 | 설명 |
|---|---|---|
| 프로토콜 | `http` | 통신에 사용할 규칙 |
| 서버 주소 | `www.oracle.com` | 웹 서버의 인터넷 주소 |
| 포트 번호 | `80` | 서버 프로그램이 연결을 기다리는 통신 포트 |
| 경로명 | `/technetwork/java/` | 서버 내부의 폴더 경로 |
| 파일 이름 | `index.html` | 요청할 웹 페이지 파일 |

대표적인 프로토콜에는 HTTP, HTTPS, FTP, File, Telnet, Mailto 등이 있다.

---

## 5. HTTP 통신

**HTTP(HyperText Transfer Protocol)**는 웹 브라우저와 웹 서버가 웹 자원을 주고받을 때 사용하는 통신 규칙이다.

HTTP 통신의 기본 과정은 다음과 같다.

```text
1. 브라우저가 웹 서버에 연결을 요청한다.
2. 웹 서버가 연결을 수락한다.
3. 브라우저가 HTML 페이지를 요청한다.
4. 서버가 요청받은 페이지를 읽는다.
5. 서버가 HTML 페이지를 전송한다.
6. 브라우저가 HTML을 해석하여 출력한다.
```

웹 브라우저가 필요한 자원을 전송받은 뒤 연결을 종료하는 방식은 서버의 부담을 줄여 많은 사용자의 동시 접속을 처리하는 데 유리하다.

## 6. 웹의 시작과 성공 원인

### 6.1 웹의 시작

웹은 **Tim Berners-Lee**의 아이디어에서 시작되었다.

- 1989년: 웹 개념 제안
- 1990년: WorldWideWeb 프로젝트 시작
- HTTP 기반의 서버-클라이언트 모델 제시
- HTML과 하이퍼링크 개념 구현
- 최초의 웹 서버와 웹 브라우저 개발

### 6.2 웹이 성공한 이유

#### 1. 만들기 쉬운 웹 문서

- HTML 문법이 단순하고 직관적임
- HTML 파일은 텍스트 문서임
- 일반 텍스트 편집기로도 작성 가능함

#### 2. 효율적인 HTTP 통신

- 필요한 자원을 전송한 뒤 연결을 종료함
- 웹 서버의 연결 부담이 비교적 낮음
- 많은 사용자의 동시 접속 처리에 유리함

#### 3. 서버와 브라우저의 작업 분담

- 웹 서버: 요청받은 자원 전송
- 웹 브라우저: HTML을 해석하고 화면에 출력
- 역할을 나누어 서버의 작업 부담을 낮춤

## 7. 웹 페이지의 3대 구성 요소

웹 페이지는 **HTML, CSS, JavaScript**로 구성된다.

| 기술 | 역할 | 비유 |
|---|---|---|
| HTML | 웹 페이지의 구조와 내용 작성 | 건물의 뼈대 |
| CSS | 색상, 글꼴, 배치 등 모양 지정 | 건물의 디자인 |
| JavaScript | 사용자 동작 처리와 기능 구현 | 건물의 작동 장치 |

### 7.1 HTML

- 웹 페이지의 구조와 콘텐츠를 작성하는 언어
- 제목, 문단, 이미지, 표, 목록 등을 태그로 표현

```html
<h1>웹 프로그래밍</h1>
<p>HTML은 웹 페이지의 구조를 작성한다.</p>
```

### 7.2 CSS

- 웹 페이지의 색상, 크기, 여백, 배치 등 시각적 표현 담당

```css
h1 {
  color: blue;
}
```

### 7.3 JavaScript

- 클릭, 입력, 계산, 화면 변경 등 웹 페이지의 동작 담당

```javascript
alert("Hello, Web!");
```

HTML, CSS, JavaScript는 각자의 역할에 맞게 분리하여 개발하는 것이 중요하다.

## 8. HTML5의 등장

### 8.1 HTML

HTML은 1990년 Tim Berners-Lee가 정의한 웹 문서 작성 언어이다. 표준화된 태그를 사용해 웹 페이지를 구성한다.

대표적인 태그의 예시는 다음과 같다.

```html
<img>
<hr>
<table>
<li>
```

### 8.2 HTML5의 등장 배경

기존 웹 환경에는 다음과 같은 문제가 있었다.

1. **비표준 기술의 혼재**
   - ActiveX, Flash, 각종 플러그인 사용
   - 브라우저마다 기능과 실행 결과가 다름

2. **인터넷 기기의 다양화**
   - PC뿐만 아니라 스마트폰과 태블릿에서도 웹 사용
   - 기존 PC 중심의 웹 페이지는 모바일 기기 지원에 한계가 있었음

3. **범용 웹 표준의 필요**
   - 특정 운영체제나 장치에 의존하지 않는 표준 필요
   - PC와 모바일에서 모두 작동하는 웹 환경 필요

이러한 문제를 해결하기 위한 새로운 웹 표준으로 HTML5가 등장하였다.

### 8.3 HTML5 표준의 의의

HTML5 표준은 W3C와 WHATWG를 중심으로 발전하였다.

주요 의의는 다음과 같다.

- 문서 구조는 HTML5로 작성
- 문서 모양은 CSS3로 작성
- 문서 동작은 JavaScript로 작성
- 문서의 모양만을 위한 기존 HTML 태그와 속성 축소
- 운영체제와 장치에 대한 의존성 감소
- ActiveX나 Flash 없이 다양한 기능 구현
- 웹 애플리케이션 개발을 위한 JavaScript API 제공

## 9. HTML5의 주요 기능

HTML5는 단순히 웹 문서를 작성하는 태그뿐만 아니라 웹 애플리케이션을 만들기 위한 여러 API를 제공한다.

| 기능 | 설명 |
|---|---|
| Web Form | 사용자 입력을 받는 폼 기능 |
| Audio / Video | 플러그인 없이 미디어 재생 |
| Canvas | JavaScript를 이용한 그래픽 표현 |
| SVG | 크기를 변경해도 품질이 유지되는 벡터 그래픽 |
| Web Storage | 브라우저에 데이터 저장 |
| IndexedDB | 브라우저 내부의 구조화된 데이터 저장 |
| File I/O | 사용자가 선택한 파일 처리 |
| Geolocation API | 사용자 위치 정보 활용 |
| Web Worker | 백그라운드 작업 처리 |
| WebSocket | 서버와의 양방향 실시간 통신 |
| Offline Web Application | 네트워크 연결이 없는 상태를 고려한 웹 실행 |

> 강의자료에는 Web SQL Database도 HTML5 관련 기능으로 제시되어 있다.

### HTML5 도입 전후 비교

| 구분 | HTML5 이전 | HTML5 도입 이후 |
|---|---|---|
| 미디어 및 애니메이션 | Flash, 플러그인 등에 의존 | 브라우저의 표준 기능으로 처리 |
| 실행 환경 | 주로 PC 중심 | PC, 태블릿, 스마트폰 지원 |
| 호환성 | 브라우저별 차이가 큼 | 웹 표준 기반으로 호환성 향상 |
| 장치 의존성 | 특정 기술과 운영체제에 의존 | 플랫폼 의존성 감소 |

## 10. HTML5 문서 작성 및 실행

### 10.1 편집기

HTML 문서는 텍스트 파일이므로 일반 텍스트 편집기로 작성할 수 있다.

- 메모장
- Sublime Text
- Atom
- Eclipse
- 기타 코드 편집기

WYSIWYG 편집기는 실제 출력 모습을 확인하며 작성할 수 있고, 태그 정보나 간단한 오류 검사 기능을 제공한다.

### 10.2 저장 방법

- 파일 확장자를 `.html`로 저장
- 문자 인코딩은 `UTF-8` 사용
- HTML, CSS, JavaScript 파일 모두 UTF-8로 저장하는 것이 기본

간단한 HTML5 문서의 예시는 다음과 같다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <title>첫 번째 웹 페이지</title>
</head>
<body>
  <h1>Hello, HTML5!</h1>
  <p>웹 프로그래밍을 시작합니다.</p>
</body>
</html>
```

### 10.3 실행 방법

1. 편집기에서 HTML 문서를 작성한다.
2. `.html` 확장자와 UTF-8 인코딩으로 저장한다.
3. 저장한 HTML 파일을 더블 클릭한다.
4. 웹 브라우저에서 출력 결과를 확인한다.

## 11. 브라우저 개발자 도구

브라우저의 개발자 도구를 사용하면 HTML, CSS, JavaScript를 확인하고 오류를 찾을 수 있다.

### 개발자 도구 열기

- 키보드에서 `F12` 누르기
- 웹 페이지에서 마우스 오른쪽 버튼 클릭 후 **검사** 선택

### 주요 활용

- HTML 요소와 CSS 스타일 확인
- Sources 메뉴에서 소스 코드 확인
- JavaScript 중단점(Breakpoint) 설정
- 코드를 한 줄씩 실행하며 동작 분석
- 오류 메시지 확인 및 디버깅
